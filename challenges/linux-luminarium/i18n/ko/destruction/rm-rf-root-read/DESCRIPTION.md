파일 시스템을 통째로 날렸을 때의 여파를 파고들어 봅시다.
이제 여러분은 능숙한 `rm` 사용자이지만, 앞에서는 파일 시스템의 잡동사니를 치우고 나면 `/challenge/check`가 플래그를 출력해 주었습니다.
그러지 않았다면 어땠을까요?
`cat` 없이 그 `/flag`를 어떻게 읽을까요?

[문서 소화하기](/linux-luminarium/man) 모듈에서 어떤 셸 명령은 _빌트인_ 이라고 했던 것을 떠올려 보세요.
`ls`나 `cat` 같은 것은 아니지만, ([셸 변수](/linux-luminarium/variables) 모듈에서 보았듯 파일을 읽을 수 있는!) `read`는 빌트인입니다.
즉 파일 시스템을 통째로 날려버려도, 이미 실행 중인 bash 인스턴스가 있다면 파일을 읽을 수 있다는 뜻입니다!

이 챌린지는 그것을 직접 해보게 합니다.
앞의 것과 거의 같지만, 시스템을 파괴한 뒤 플래그를 직접 읽어야 합니다.
전부 `rm`하고 나면, 앞서 실행해 둔 `/challenge/check`가 `/flag` 파일을 복원하고 읽을 수 있게 만들어 줍니다.
그러면 그것을 `read`하면 됩니다!
