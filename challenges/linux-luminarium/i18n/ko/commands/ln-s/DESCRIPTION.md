리눅스(혹은 컴퓨터)로 실제 일을 어느 정도 오래 하다 보면 언젠가 이런 상황을 만나게 됩니다: 두 프로그램이 같은 데이터에 접근해야 하는데, 각 프로그램은 그 데이터가 서로 다른 위치에 있기를 기대하는 상황이죠.
다행히 리눅스는 이 난처함에 대한 해법을 제공합니다: _링크(link)_ 입니다.

링크에는 두 종류가 있습니다: _하드(hard)_ 링크와 _소프트(soft)_ 링크(_심볼릭(symbolic)_ 링크라고도 합니다).
비유로 둘을 구분해 봅시다:

- **하드** 링크는 여러분의 아파트를 여러 개의 주소로 부르되 그 주소들이 모두 똑같은 곳으로 곧장 이어지는 것입니다(예: `2호` 대 `2세대`).
- **소프트** 링크는 이사를 간 뒤 우체국이 예전 집으로 온 우편물을 새 집으로 자동 전달해 주는 것입니다.

파일 시스템에서 파일은 개념적으로 그 파일의 내용이 있는 주소라고 볼 수 있습니다.
하드 링크는 그 데이터를 가리키는 또 하나의 주소입니다. 하드 링크에 접근하는 것과 원본 파일에 접근하는 것은 완전히 동일하며, 둘 다 필요한 데이터를 곧바로 내어줍니다.
반면 소프트/심볼릭 링크는 원본 파일의 *이름* 을 담고 있습니다.
심볼릭 링크에 접근하면 리눅스는 그것이 심볼릭 링크임을 알아채고, 원본 파일 이름을 읽은 뒤 (보통은) 자동으로 그 파일에 접근합니다.
대부분의 경우 두 방식 모두 결국 원본 데이터에 접근하게 되지만, 그 메커니즘은 다릅니다.

대부분의 사람에게는 하드 링크가 더 단순하게 들리겠지만(실제로 위에서 하드 링크는 한 문장, 소프트 링크는 두 문장으로 설명했죠), 하드 링크에는 여러 단점과 구현상의 함정이 있어서 소프트/심볼릭 링크가 훨씬 더 널리 쓰입니다.

이 챌린지에서는 심볼릭 링크(_심링크(symlink)_ 라고도 합니다)를 배웁니다.
심볼릭 링크는 `ln` 명령어로 `ln -s 대상 링크이름` 형태로 만듭니다.
`대상`은 링크가 가리킬 경로이고, `링크이름`은 새로 만들 경로입니다.
예를 들면:

```console
hacker@dojo:~$ cat /tmp/myfile
This is my file!
hacker@dojo:~$ ln -s /tmp/myfile /home/hacker/ourfile
hacker@dojo:~$ cat ~/ourfile
This is my file!
hacker@dojo:~$
```

심링크에 접근했더니 원본 파일의 내용이 나오는 것을 볼 수 있습니다!
이 예시에서 `/tmp/myfile`이 대상이고 `/home/hacker/ourfile`이 링크 이름입니다.

심링크인지는 몇 가지 방법으로 알아낼 수 있습니다.
예를 들어 파일 이름을 받아 그 파일이 어떤 종류인지 알려주는 `file` 명령어는 심링크를 알아봅니다:

```console
hacker@dojo:~$ file /tmp/myfile
/tmp/myfile: ASCII text
hacker@dojo:~$ file ~/ourfile
/home/hacker/ourfile: symbolic link to /tmp/myfile
hacker@dojo:~$
```
