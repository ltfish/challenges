표준 출력과 마찬가지로 명령의 에러 채널도 리다이렉트할 수 있습니다.
여기서는 *파일 디스크립터 번호* 를 배웁니다.
파일 디스크립터(FD)는 리눅스에서 통신 채널을 *기술하는* 번호입니다.
알아채지 못했을 뿐, 여러분은 이미 이것을 써 왔습니다.
이미 익숙한 것이 셋 있습니다:

- FD 0: 표준 입력
- FD 1: 표준 출력
- FD 2: 표준 에러

프로세스의 통신을 리다이렉트할 때는 FD 번호로 지정하는데, 어떤 번호는 생략되어 있습니다.
예를 들어 번호 없는 `>`는 `1>`를 뜻하며, FD 1(표준 출력)을 리다이렉트합니다.
따라서 다음 두 명령은 같습니다:

```console
hacker@dojo:~$ echo hi > asdf
hacker@dojo:~$ echo hi 1> asdf
```

여기까지 오면 에러를 리다이렉트하는 것은 꽤 쉽습니다.
표준 에러로 데이터를 내보낼 수 있는 명령(예: `/challenge/run`)이 있다면 이렇게 하면 됩니다:

```console
hacker@dojo:~$ /challenge/run 2> errors.log
```

이렇게 하면 표준 에러(FD 2)가 `errors.log` 파일로 리다이렉트됩니다.
게다가 여러 파일 디스크립터를 동시에 리다이렉트할 수도 있습니다!
예를 들면:

```console
hacker@dojo:~$ some_command > output.log 2> errors.log
```

이 명령은 출력을 `output.log`로, 에러를 `errors.log`로 리다이렉트합니다.

이제 실제로 해봅시다!
이 챌린지에서는 앞서처럼 `/challenge/run`의 출력을 `myflag`로, "에러"(여기서는 안내문입니다)를 `instructions`로 리다이렉트해야 합니다.
전부 리다이렉트했으니 터미널에는 아무것도 찍히지 않을 것입니다!
제대로 해내면 안내와 피드백은 `instructions`에서, 플래그는 `myflag`에서 볼 수 있습니다!
