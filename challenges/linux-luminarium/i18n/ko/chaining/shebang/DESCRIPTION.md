셸 스크립터로서의 새 삶이 순조롭게 시작되고 있습니다!
그런데 지금까지 여러분의 셸 스크립트는 _셸에서만 실행할 수 있습니다_.
앞 레벨에서는 (`bash` 셸에서 스크립트를 실행했으니) 잘 동작했지만, 예를 들어 Python(또는 다른 언어)으로 작성된 프로그램이 여러분의 스크립트를 실행하려 한다면 동작하지 않습니다.

리눅스에서 프로그램이 실행되면, 리눅스 커널은 먼저 그 파일을 살펴 어떻게 실행할지 결정합니다.
이때 확장자는 쓰지 _않습니다_(그래서 셸 스크립트에 `.sh`, Python 스크립트에 `.py` 확장자를 꼭 붙일 _필요_ 가 없는 것입니다).
대신 리눅스는 파일의 첫 몇 바이트에서 그 정보를 찾습니다.

프로그램의 종류는 여러 가지지만, 프로그램 파일이 `#!` 문자로 시작하면(흔히 "[셔뱅(shebang)](https://en.wikipedia.org/wiki/Shebang_(Unix))"이라고 부릅니다) 리눅스는 그 파일을 _인터프리터로 실행되는 프로그램_ 으로 보고, 그 줄의 나머지를 _인터프리터_ 의 경로로 봅니다.
그런 다음 프로그램 파일의 경로를 유일한 인자로 주어 그 인터프리터를 실행합니다.

다음 셸 스크립트를 봅시다:

```bash
#!/bin/bash

echo "Hello Hackers!"
```

이렇게 실행할 수 있습니다:

```console
hacker@dojo:~$ chmod a+x script.sh
hacker@dojo:~$ ./script.sh
Hello Hackers!
hacker@dojo:~$
```

`./script.sh`를 실행하면 리눅스는 파일을 열어 첫 줄을 읽고 `/bin/bash`를 인터프리터로 뽑아낸 뒤, `/bin/bash ./script.sh`를 실행해서 스크립트를 띄웁니다!

셔뱅 줄은 파일의 맨 첫 줄이어야 한다는 점에 주의하세요. 그 앞에 빈 줄이나 공백이 있으면 안 됩니다!

이 챌린지에서는 `/home/hacker/solve.sh`에 제대로 된 셔뱅을 갖추고 "hack the planet"을 출력하는 스크립트를 만드세요.
실행 가능하게 만드는 것을 잊지 말고, `/challenge/run`을 실행해서 스크립트가 제대로 동작하는지 확인하세요!

**재미있는 사실:**
흔히 볼 수 있는 셔뱅들:
- bash 스크립트에는 `#!/bin/bash`
- Python 스크립트에는 `#!/usr/bin/python3`
- POSIX 셸 스크립트에는 `#!/bin/sh` --- `bash`보다 더 원시적인 선조로 기능은 적지만, 리눅스가 아닌 시스템과의 호환성은 더 좋습니다!
