gdb를 비롯한 디버거는 디버깅 대상 프로그램을 _실행하면서_ 관찰해 실행 중의 동작에 대한 정보를 드러냅니다.
앞 레벨에서는 저희가 프로그램을 대신 실행해 주었습니다.
여기서는 마법을 조금 줄이겠습니다. 프로그램의 실행은 여러분이 시작해야 하고, 나머지(예: 비밀 값 알아내기)는 저희가 하겠습니다.

이제 gdb를 실행하면 결국 이런 모습의 명령 프롬프트가 나타납니다:

```gdb
(gdb) 
```

프로그램은 `starti` 명령으로 시작합니다:

```gdb
(gdb) starti
```

`starti`는 프로그램을 맨 첫 **i**nstruction에서 **start** 합니다.
프로그램이 실행되고 나면 다른 gdb 명령으로 실제 실행 중 상태를 살펴볼 수 있습니다.
실행 중인 코드부터 시작하겠습니다. `disassemble` 명령으로 디스어셈블할 수 있습니다!
예를 들면:

```gdb
(gdb) disassemble
Dump of assembler code for function main:
=> 0x0000000000401000 <+0>:     mov    rdi,0x539
   0x0000000000401007 <+7>:     mov    rdi,0x0
   0x000000000040100e <+14>:    mov    rax,0x3c
   0x0000000000401015 <+21>:    syscall
End of assembler dump.
```

objdump 챌린지에서 본 것과 같은 프로그램이 이번에는 gdb 안에서 돌고 있습니다.
앞서처럼 디스어셈블리를 읽어 비밀을 캐낼 수 있고, 나중에는 더 깊이 파고들 것입니다!
지금은 gdb에 바이너리를 불러온 뒤 `starti`를 실행하세요. 나머지는 저희가 처리하겠습니다.
