지난 레벨에서는 `stepi`로 `pop rdi`를 실행하고 `print $rdi`로 비밀을 읽을 수 있었습니다.
이번에는 `pop`이 아예 없습니다. 프로그램이 그냥 곧바로 종료합니다:

```text
mov    rdi,0x0
mov    rax,0x3c
syscall             <- exit(0) --- the secret was never read!
```

비밀은 여전히 `argc`이고 스택 맨 꼭대기에 놓여 있지만, 프로그램이 그것을 레지스터로 불러오지 않습니다.
메모리를 직접 살펴봐야 합니다!

GDB의 `x`(e**x**amine) 명령으로 메모리 내용을 들여다볼 수 있습니다.
앞에서 배웠듯 스택 포인터(`$rsp`)는 처음에 `argc`를 바로 가리키므로, 이렇게 읽을 수 있습니다:

```text
x $rsp
```

가서 해보세요!

1. 프로그램을 시작합니다
2. 스택 꼭대기를 살펴봅니다
3. gdb를 종료하고 그 값을 `/challenge/submit-number`로 제출합니다

----

**참고:**
`x`는 기본적으로 값을 _16진수_ 로 보여줍니다.
명령 뒤에 `/`를 붙여 표시 형식을 바꿀 수 있습니다.
예를 들어 10진수로 보고 싶다면 `x/d $rsp`를 쓰세요.
어느 쪽이든 `/challenge/submit-number`는 16진수(예: `0x2a`)와 10진수(예: `42`)를 모두 받습니다.
