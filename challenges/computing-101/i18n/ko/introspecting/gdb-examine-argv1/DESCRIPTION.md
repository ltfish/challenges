지난 레벨에서는 `x`로 스택 꼭대기의 `argc`를 읽었습니다.
그런데 스택에는 `argc` 말고도 더 있습니다!

인자 개수 바로 뒤에 스택은 각 프로그램 인자를 가리키는 _포인터_ 를 저장합니다.
이것들은 메모리에 저장된 _주소_ 입니다. `$rsp+16`은 인자 텍스트를 직접 담고 있는 것이 아니라, 그 텍스트가 있는 _주소_ 를 담고 있습니다.

예를 들어 프로그램을 `/challenge/debug-me Hi`로 실행하면:

```text
     Address    │ Contents
   +────────────────────────────+
   │  rsp + 0   │ 2             │◀── argc
   +────────────────────────────+
   │  rsp + 8   │ 0x1234000     │──────┐
   +────────────────────────────+      │
   │  rsp + 16  │ 0x1234560     │────┐ │
   +────────────────────────────+    │ │
                                     │ │
                                     │ │
     Address    │ Contents           │ │
   +──────────────────────────────+  │ │
   │ 0x1234000  │ "/challenge/..."│◀─│─┘ the program name
   +──────────────────────────────+  │
   │ ...        │ ...                │
   +──────────────────────────────+  │
   │ 0x1234560  │ "Hi"            │◀─┘   the first argument
   +──────────────────────────────+
```

실제 인자 데이터를 얻으려면 두 번 역참조해야 합니다. 한 번은 스택에서 포인터를 얻으려고, 또 한 번은 그 포인터를 따라가 문자열을 읽으려고요.

이 레벨에서는 플래그 그 자체가 첫 번째 인자로 넘어옵니다!
프로그램은 그것을 쓰지 않고 그냥 종료하지만, 플래그는 바로 그 메모리에 있습니다.

그것을 찾으려면 표시 모드가 다른 `x` 명령 두 개가 필요합니다:

**첫째:**
첫 번째 인자의 _포인터_ 가 필요합니다.
전에 해본 일이지만, 이번에는 gdb에서 합니다.

```text
x/a $rsp+16
```

`/a`는 값을 메모리 **a**ddress로 보여주라고 `x`에 알려줍니다.
`0x7ffc001c4750` 같은 아주 큰 16진수가 보일 것입니다.

**둘째:**
그 주소에 있는 첫 번째 인자의 텍스트를 읽습니다:

```text
x/s 0x7ffc001c4750
```

`/s`는 값을 **s**tring으로 보여주라고 `x`에 알려줍니다.
주소는 1단계에서 얻은 것으로 바꾸세요.
그러면 플래그가 보입니다!

가서 해보세요!

1. 프로그램을 시작합니다
2. `x/a $rsp+16`으로 첫 번째 인자의 주소를 얻습니다
3. `x/s <address>`로 플래그 문자열을 읽습니다
