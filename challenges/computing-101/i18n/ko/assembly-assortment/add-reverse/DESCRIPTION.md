앞 챌린지에서는 `cmp` 명령어에서 비밀번호 문자를 직접 찾아 프로그램을 리버싱했습니다.
이번에는 프로그램이 비교하기 전에 여러분의 입력을 _변형_ 합니다.
검사를 통과하려면 그 연산을 이해하고 머릿속에서 거꾸로 되돌려야 합니다!

`/challenge/reverse-me`에 새 SUID 바이너리가 있습니다.
이 프로그램은 첫 번째 인자의 첫 바이트에 어떤 연산을 하고, 그 결과를 하드코딩된 값과 비교합니다.
비교를 통과하면 플래그를 읽어 출력하고, 아니면 조용히 종료합니다.

여기서 새로 나오는 명령어는 `add`입니다:

```asm
add rax, 42
```

이것은 `rax` 레지스터에 42를 더하고 그 결과로 `rax`를 갱신합니다.
다음 코드는 `rax`가 99가 되게 합니다:

```asm
mov rax, 57
add rax, 42
```

다른 많은 명령어처럼 `add`도 메모리, 레지스터, 즉시값을 다룰 수 있습니다. 이 바이너리를 `objdump -d -M intel /challenge/reverse-me`로 디스어셈블하면 이런 것이 보일 수 있습니다:

```
add    BYTE PTR [rax],0x2a
cmp    BYTE PTR [rax],0x96
```

이것은 (메모리에 있는) 입력의 첫 바이트에 `0x2a`(42)를 더한 뒤, 그 결과가 `0x96`(150)인지 확인합니다.
어떤 문자가 필요한지 알아내려면 연산을 되돌리면 됩니다: `150 - 42 = 108`(`6c`).
`man ascii`를 보면 `0x6c`는 문자 `'l'`입니다.
그러므로 이 경우 필요한 입력 문자는 `l`입니다(다시 말하지만 16진수 값과 문자를 오갈 때는 `man ascii`가 좋은 친구입니다)!

문자를 알아냈으면 프로그램을 실행하세요:

```console
hacker@dojo:~$ /challenge/reverse-me YOUR_CHARACTER_HERE
```

이제 여러분 차례입니다!
가서 플래그를 얻으세요.

----
**경고**:
`/challenge/reverse-me`는 **SUID** 바이너리입니다. `/flag`를 읽을 수 있도록 높은 권한으로 실행되죠.
그런데 **프로그램을 디버깅하면 SUID 권한이 떨어지므로**, gdb 아래에서 실행하면 내부의 `open("/flag")` 시스템 콜이 **조용히** 실패합니다.
바이너리를 _이해_ 하는 데는 gdb나 `objdump`를 쓰되, 플래그를 얻으려면 (gdb 밖에서) **직접** 실행하세요.
