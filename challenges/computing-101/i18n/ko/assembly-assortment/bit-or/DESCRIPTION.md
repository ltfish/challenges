비트 `or`도 두 값을 비트 단위로 비교하지만 규칙이 `and`와 반대입니다. 두 입력 비트 중 *하나라도* `1`이면 출력 비트가 `1`이죠.
그래서 `or`는 비트를 *켜는* 도구입니다. 특정 비트만 켜고 나머지는 그대로 두는 것이죠.

마스크가 `1`인 자리는 결과 비트가 `1`로 강제되고, `0`인 자리는 원래 비트가 그대로 통과합니다:

```
  0100 0001   ('A', 0x41)
| 0010 0000   (turn on 0x20)
---------
  0110 0001   ('a', 0x61)
```

이 예시는 실제로 쓰이는 요령입니다.
ASCII에서 대문자와 그 소문자 짝은 오직 `0x20` 대소문자 비트(오른쪽에서 여섯 번째 비트)만 다릅니다.
소문자 값은 대문자 값에 그 비트를 켠 것입니다:

| 대문자    | 소문자    |
|--------------|--------------|
| `A` = `0x41` | `a` = `0x61` |
| `H` = `0x48` | `h` = `0x68` |
| `P` = `0x50` | `p` = `0x70` |
| `Z` = `0x5A` | `z` = `0x7A` |

`or`는 `and`와 같은 방식으로 피연산자를 받습니다. 바꿀 값, 그다음 마스크죠.
`or`로 대소문자 비트를 켜면 어떤 대문자든 소문자가 됩니다.

`rdi`로 대문자 ASCII 글자를 받아 그 소문자 형태를 `rax`로 반환하는 함수를 작성하세요.
이름은 `chr_lower`로 하세요. 함수 이름은 하는 일을 따서 지어야 코드가 커져도 읽기 좋습니다.
`.global chr_lower`로 내보내세요.

공유 라이브러리로 빌드해서 채점기에 넘기세요:

```console

hacker@dojo:~$ ld -shared -o chr_lower.so chr_lower.o
hacker@dojo:~$ /challenge/check chr_lower.so
```
