CPU는 아주 단순하게 생각합니다.
데이터를 옮기고, 데이터를 바꾸고, 데이터를 근거로 판단하고, 그 결과에 따라 행동합니다.
이 데이터는 대개 _레지스터(register)_ 에 저장됩니다.

간단히 말해 레지스터는 데이터를 담는 그릇입니다.
CPU는 레지스터에 데이터를 넣고, 레지스터끼리 데이터를 옮기는 등의 일을 합니다.
하드웨어 수준에서 이 레지스터는 아주 비싼 칩으로 구현되며, 놀랄 만큼 미세한 공간에 욱여넣어지고, 빛의 속도 같은 물리적 개념까지 성능에 영향을 주는 주파수로 접근됩니다.
그래서 CPU가 가질 수 있는 레지스터의 수는 _극도로_ 제한됩니다.
CPU 아키텍처마다 레지스터 개수도 이름도 다르지만, 보통 프로그램 코드가 아무 용도로나 쓸 수 있는 "범용" 레지스터가 10~20개쯤 있고, 특수한 용도로 쓰는 것이 수십 개까지 있습니다.

x86의 현대적 형태인 x86\_64에서 프로그램은 16개의 범용 레지스터를 쓸 수 있습니다.
이 챌린지에서는 그중 첫 번째인 `rax`를 배웁니다.
안녕, Rax!

x86 레지스터 하나인 `rax`는 어마어마하게 복잡한 x86 CPU 설계의 아주 작은 조각이지만, 여기서 시작하겠습니다.
다른 레지스터와 마찬가지로 `rax`는 적은 양의 데이터를 담는 그릇입니다.
`mov` 명령어로 `rax`에 데이터를 _옮깁니다_.
명령어는 _연산자(operator)_ (여기서는 `mov`)와, 추가 데이터를 나타내는 _피연산자(operand)_ (여기서는 목적지인 `rax`와 거기에 저장할 값)로 지정합니다.

예를 들어 값 `1337`을 `rax`에 저장하고 싶다면 x86 어셈블리는 이렇게 생겼습니다:

```assembly
mov rax, 1337
```

몇 가지가 보입니다:

1. 목적지(`rax`)를 출처(값 `1337`)보다 _먼저_ 씁니다.
2. 피연산자는 쉼표로 구분합니다.
3. _정말_ 간단합니다!

이 챌린지에서는 여러분의 첫 어셈블리를 작성합니다.
값 `60`을 `rax`로 옮겨야 합니다.
