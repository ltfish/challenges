스택에는 `argc`와 `argv`만 있는 것이 아닙니다!
인자 목록 바로 뒤에 커널은 [리눅스 루미나리움](/linux-luminarium)에서 배운 **환경 변수** 를 놓아둡니다.
`argv`와 마찬가지로 이것들도 문자열을 가리키는 포인터 배열로 스택에 저장되며, 각 문자열은 `PATH=/usr/bin:...`, `HOME=/home/hacker`, `PWN=COLLEGE`처럼 변수의 이름과 값을 함께 담고 있습니다.

인자 없이(즉 `argc`가 1이고 `argv`의 유일한 문자열이 프로그램 이름인) 그리고 `FLAG`라는 환경 변수 하나만 두고 프로그램을 실행하면, 시작 시점의 스택 배치는 이런 모습일 수 있습니다:

```text
     Address    │ Contents
   +────────────────────────+
   │ rsp + 0    │ 1         │ ◀─── argc
   +────────────────────────+
   │ rsp + 8    │ rsp + 128 │──┐  argv[0]: pointer to the program name
   +────────────────────────+  │
   │ rsp + 16   │ 0         │  │  NULL (end of argv)
   +────────────────────────+  │
   │ rsp + 24   │ rsp + 200 │──┼──┐  envp[0]: pointer to the first env var
   +────────────────────────+  │  │
   │ rsp + 32   │ 0         │  │  │  NULL (end of envp)
   +────────────────────────+  │  │
                               │  │
     Address    │ Contents     │  │
   +────────────────────────+  │  │
   │ rsp + 128  │ "/tmp/..."│◀─┘  │  the program name
   +────────────────────────+     │
   │ ...        │ ...       │     │
   +────────────────────────+     │
   │ rsp + 200  │ "FLAG=..."│◀────┘  the first env var: the `FLAG` variable
   +────────────────────────+
```

새로 눈여겨볼 것이 두 가지 있습니다:

1. `argv`와 `envp`는 모두 **NULL 포인터로 끝납니다**. 커널이 각 포인터 목록의 끝에 `NULL` 포인터를 써두죠.
   프로그램(그리고 여러분!)은 그것으로 각 목록이 어디서 끝나는지 압니다. `NULL`을 만날 때까지 포인터를 따라가면 되니까요.
   그림에서 `rsp+16`의 `NULL`이 `argv`의 끝을, `rsp+32`의 또 다른 `NULL`이 `envp`의 끝을 표시하는 것이 보입니다.

2. `envp` 문자열은 `NAME=VALUE` 형태입니다(예: `PATH=/usr/bin:/bin`).
   그러니 `envp[0]`은 첫 환경 변수의 이름으로 시작하는 문자열을 가리킵니다.

이 챌린지에서는 `FLAG` 환경 변수를 실제 플래그로 설정하고, 인자도 다른 환경 변수도 없이 여러분의 프로그램을 실행합니다.
즉 `[rsp+24]`가 `FLAG=...` 문자열의 포인터를 담게 되며, 그것을 `write()`하면 플래그를 얻을 수 있습니다!

이것은 프로그램 전체를 다루는 레벨이므로 공유 라이브러리가 아니라 실행 파일을 제출하세요.
프로그램을 어셈블하고 링크한 뒤 그 실행 파일을 검사기에 넘기세요:

```console
hacker@dojo:~$ as -o envp.o envp.s
hacker@dojo:~$ ld -o envp envp.o
hacker@dojo:~$ /challenge/check envp
```
