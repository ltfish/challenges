앞 레벨에서는 커널이 스택에 놓아둔 포인터인 `envp[0]`을 읽었습니다. 포인터 표 위쪽의 문자열 영역을 _가리키는_ 포인터였죠.
여기서도 같은 배치가 적용됩니다:

```text
     Address    │ Contents
   +────────────────────────+
   │ rsp + 0    │ 1         │ ◀─── argc
   +────────────────────────+
   │ rsp + 8    │ rsp + 128 │───────┐  argv[0]: pointer to the program name
   +────────────────────────+       │
   │ rsp + 16   │ 0         │       │  NULL (end of argv)
   +────────────────────────+       │
   │ rsp + 24   │ rsp + 200 │─────┐ │  envp[0]: pointer to the first env var
   +────────────────────────+     │ │
   │ rsp + 32   │ 0         │     │ │  NULL (end of envp)
   +────────────────────────+     │ │
                                  │ │
  ┌───────────────────────────────│─┘
  │                               │
  │   Address   │ Contents        │
  │ +──────────────────────────+  │
  │ │ rsp + 128 │ "/tmp/..."   │◀─┘ the program name
  │ +──────────────────────────+
  │ │ ...       │ ...          │
  │ +──────────────────────────+
  └▸│ rsp + 200 │ "FOO=..."    │ ◀─ the first env var
    +──────────────────────────+
```

그런데 실제 주소(`rsp`나 `rsp+200`이 가리키게 되는 실제 주소 등)는 어디서 올까요?

프로그램이 실행될 때 커널은 어떤 시작 주소에서부터 **스택을 거꾸로 채웁니다**.
거기서부터 환경 문자열을 놓고(작은 주소 쪽으로 "자라며"), 그다음 인자 문자열, 다른 메타데이터, 그리고 `envp[]`와 `argv[]` 포인터 표, 마지막으로 그 구조의 가장 왼쪽에 `argc`를 놓습니다.
`rsp`가 가리키게 되는 곳이 바로 거기입니다.

여기에는 흥미로운 결과가 따릅니다. **환경(또는 프로그램 인자)에 바이트를 더 많이 넣을수록, 커널은 나머지 모든 것을 스택의 더 "왼쪽"으로 밀어냅니다**.
환경 바이트가 하나 늘면 `rsp`는 더 작은 주소에 놓이고, 인자 문자열 영역은 한 바이트 더 "왼쪽"에 자리하며, (그 영역을 가리키는 포인터인) `argv[0]`은 1만큼 작은 값을 담게 됩니다.

여기서 `env -i`는 "다음 명령을 빈 환경으로 실행하라"는 뜻입니다. `-i` 뒤에 넣는 `NAME=VALUE` 쌍이 자식 프로그램이 받는 유일한 환경 문자열이 됩니다.
이 챌린지에서는 먼저 `env -i /challenge/program`으로 깨끗한 기준을 잡아, 프로그램이 `argv[0]`이 어느 주소에 있기를 원하는지 확인하세요.
그런 다음 정확히 하나의 환경 변수를, 값에 딱 맞는 개수의 `x`를 넣어 다시 실행해서 `argv[0]`을 그 주소로 옮기세요.
셸 자신의 변수까지 스택에 올라가 계산이 어긋나지 않도록 두 번 다 `env -i`를 쓰세요:

```text
hacker@dojo:~$ env -i /challenge/program
hacker@dojo:~$ env -i FOO=xxxxxxxx /challenge/program
```

환경 문자열 전체가 스택에 놓이므로 `FOO=`와 값, 그리고 끝의 널 바이트가 모두 이동량에 들어간다는 점을 기억하세요.
프로그램을 전혀 고치지 않고 실행 방식만 바꿔서 데이터가 놓이는 위치에 영향을 주는 것입니다!
