스택과 관련해 흔히 겪는 골칫거리는 gdb 아래에서 프로그램을 띄울 때 스택 주소가 이동한다는 점입니다.
기본적으로 gdb는 자기 환경(여러분 셸의 환경에 gdb 자신이 더한 몇 가지)을 디버깅 대상 프로그램에 넘기는데, 이 추가 환경 변수들이 스택을 왼쪽으로 밀어서 `argv[0]`이 셸에서 곧바로 실행할 때와 다른 주소에 놓이게 됩니다.
지금은 그리 중요하지 않지만, 나중에 비트 단위로 정밀한 익스플로잇 코드가 gdb에서는 되는데 평범하게 도는 대상에서는 안 되는 이유를 찾을 때 큰 골칫거리가 됩니다.
그럴 때는 두 환경을 "동기화"하는 법을 익히는 것이 중요합니다.

이 챌린지는 그 기초를 가르칩니다. gdb 밖의 주소를 gdb 안의 주소와 더 잘 맞추는 것이죠.

1. gdb 아래에서 `/challenge/program`을 실행하세요(`gdb /challenge/program` 후 `run`).
   프로그램이 자기 `argv[0]`을 목표 값으로 기록합니다.
2. gdb를 종료하세요. 셸에서 `/challenge/program`을 실행하면, 셸 환경의 `argv[0]`이 목표에서 얼마나 벗어났는지 알려줍니다.
3. 환경 변수로 셸 환경을 "채워" `argv[0]`이 gdb에서 기록한 목표에 놓이게 하세요.
4. 플래그!
