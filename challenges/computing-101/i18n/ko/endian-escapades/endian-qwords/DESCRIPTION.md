여러 바이트 값이 메모리에 낮은 바이트부터 놓이므로, 그것을 레지스터로 되읽으면 바이트가 뒤집힌다는 것을 보았습니다.
레지스터 하나는 최대 8바이트인데, 그보다 넓은 값도 많습니다(그리고 CPU가 한 번에 접근하기 어려울 만큼 넓기도 하죠).

프로그램에 따라 그런 값은 레지스터 폭 단위로 차례차례 접근될 수 있습니다.
예를 들어 이 챌린지에서 만나게 될 16바이트 비밀번호를 생각해 봅시다.
16개의 ASCII 바이트를 8바이트 qword 두 개로 읽으면 이렇게 접근될 수 있습니다:

| Address     | Value  |
|-------------|--------|
| `0x1337000` | `0x41` |
| `0x1337001` | `0x42` |
| `0x1337002` | `0x43` |
| `0x1337003` | `0x44` |
| `0x1337004` | `0x45` |
| `0x1337005` | `0x46` |
| `0x1337006` | `0x47` |
| `0x1337007` | `0x48` |
| `0x1337008` | `0x49` |
| `0x1337009` | `0x4a` |
| `0x133700a` | `0x4b` |
| `0x133700b` | `0x4c` |
| `0x133700c` | `0x4d` |
| `0x133700d` | `0x4e` |
| `0x133700e` | `0x4f` |
| `0x133700f` | `0x50` |

메모리에 바이트 단위로 저장된 문자열 값이라면 그 순서는 엔디언의 영향을 받지 *않습니다*.
엔디언이 뒤집는 것은 _`mov` 후 레지스터에 들어간 바이트들_ 입니다. 각각이 여러 바이트 값이므로 낮은 바이트부터 되읽히죠.
그래서 `rdi`가 이 버퍼를 가리키고 있다면 `mov rsi, [rdi]`의 결과는 `0x4847464544434241`이 되고, 이어지는 `mov rsi, [rdi+8]`의 값은 `0x504f4e4d4c4b4a49`가 됩니다.

그러니 더 긴 값을 복원하려면, qword는 얻은 순서 그대로 두되 각 qword 안의 바이트를 뒤집으면 됩니다.

`/challenge/reverse-me`를 디스어셈블해서 입력과 비교하는 두 qword 값을 읽고, 각각을 엔디언 보정한 뒤 순서대로 이어 붙여 실행하세요:

```console
hacker@dojo:~$ objdump -d -M intel /challenge/reverse-me
hacker@dojo:~$ /challenge/reverse-me YOUR_PASSWORD_HERE
```

----
**경고**:
`/challenge/reverse-me`는 **SUID** 바이너리이므로 디버깅하면 권한이 떨어지고, 내부의 `open("/flag")`가 gdb 아래에서는 조용히 실패합니다.
읽을 때는 `objdump`를 쓰되, 플래그를 얻으려면 **직접** 실행하세요.
