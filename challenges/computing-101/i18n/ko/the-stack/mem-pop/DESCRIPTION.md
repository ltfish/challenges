스택은 왜 *스택* 이라고 부를까요?
지금까지는 다른 메모리 역참조와 마찬가지로 `mov`로 읽는 메모리 영역으로만 써 왔습니다.
하지만 스택은 말 그대로 데이터를 쌓아 올린 더미처럼 쓰라고 있는 것입니다. 꼭대기에서 값을 `pop`하는 것이죠!

`pop` 명령어가 바로 그 일을 하려고 만들어졌습니다.
`pop rdi`는 두 가지 일을 합니다:

1. `[rsp]`의 값을 `rdi`로 읽습니다(`mov rdi, [rsp]`와 똑같이).
2. `rsp`에 8을 더해, 스택 포인터를 다음 값으로 옮깁니다.

앞과 같은 예시를 쓰면:

```text
hacker@dojo:~$ /tmp/your-program hello world
```

`pop rdi` 전:

```text
    Address    │ Contents
  +───────────────────────+
  │ ...        │ ...      │
  +───────────────────────+
┌▸│ 1337000    │ 3        │  ◀── the argument count
│ +───────────────────────+
│ | 1337008    | ???      |
│ +───────────────────────+
│
└────────────────────────────┐
                             │
   Register │ Contents       │
  +────────────────────────+ │
  │ rsp     │ 1337000      │─┘
  +────────────────────────+
  │ rdi     │ 0            │
  +────────────────────────+
```

`pop rdi` 후:

```text
    Address    │ Contents
  +───────────────────────+
  │ ...        │ ...      │
  +───────────────────────+
  │ 1337000    │ 3        │
  +───────────────────────+
┌▸| 1337008    | ???      |
│ +───────────────────────+
│
└────────────────────────────┐
                             │
   Register │ Contents       │
  +────────────────────────+ │
  │ rsp     │ 1337008      │─┘
  +────────────────────────+
  │ rdi     │ 3            │
  +────────────────────────+
```

값 `3`이 스택 꼭대기에서 `rdi`로 튀어나왔고, `rsp`는 8바이트 앞으로 나아가 다음 값을 가리킵니다.
`1337000`에 있던 데이터는 여전히 메모리에 남아 있지만, 스택의 관점에서는 제거된 것입니다. `rsp`가 그것을 지나쳤으니까요.

이 챌린지에서는 `pop`으로 인자 개수를 읽어 그 값으로 종료하세요!
