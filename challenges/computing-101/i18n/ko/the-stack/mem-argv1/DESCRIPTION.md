이제 `[rsp]`를 읽어 인자 개수를 얻어 보았고, `[rsp+128]`을 읽어 오프셋에 있는 데이터도 얻어 보았습니다.
스택에 또 무엇이 있는지 살펴봅시다!

인자 개수 바로 뒤에 스택은 각 프로그램 인자를 가리키는 _포인터_ 를 저장합니다.
이것들은 메모리에 저장된 _주소_ 입니다. `[rsp+16]`은 인자 텍스트를 직접 담고 있는 것이 아니라, 그 텍스트가 있는 _주소_ 를 담고 있습니다.

예를 들어 프로그램을 `/tmp/your-program Hi`로 실행하면:

```text
     Register │ Contents
   +───────────────────────────+
   │ rsp      │ 1337000        │─┐
   +───────────────────────────+ │
                                 │
  ┌──────────────────────────────┘
  │
  │    Address    │ Contents
  │  +────────────────────────+
  │  │ ...        │ ...       │
  │  +────────────────────────+
  └▸ │ 1337000    │ 2         │  ◀── the ARGument Count (termed "argc")
     +────────────────────────+
     │ 1337008    │ 1234000   │──────┐
     +────────────────────────+      │
     │ 1337016    │ 1234560   │────┐ │
     +────────────────────────+    │ │
     │ 1337024    │ 0         │    │ │
     +────────────────────────+    │ │
                                   │ │
   ┌───────────────────────────────┘ │
   │                                 │
   │   Address   │ Contents          │
   │ +──────────────────────────+    │
   │ │ 1234000   │ "/tmp/..."   │◀───┘ the program name
   │ +──────────────────────────+
   │ │ ...       │ ...          │
   │ +──────────────────────────+
   └▸│ 1234560   │ "Hi"         │ the first argument!
     +──────────────────────────+
```

실제 인자 데이터를 얻으려면 두 번 역참조해야 합니다. 한 번은 스택에서 포인터를 얻으려고, 또 한 번은 그 포인터를 따라가 데이터를 읽으려고요.

```assembly
mov rdi, [rsp+16]   # load the first argument pointer (e.g., 1234560) from the stack
mov rdi, [rdi]      # follow the pointer to read the actual data (e.g., "Hi")
```

이 챌린지에서 여러분의 프로그램은 인자 하나와 함께 실행됩니다.
첫 번째 인자의 값을 읽어 그 값으로 종료하세요!
