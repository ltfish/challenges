앞 챌린지에서는 스택의 맨 꼭대기인 `[rsp]`의 값을 읽었습니다.
그런데 스택에는 데이터가 많이 있고, `rsp`에 _오프셋_ 을 더해 그중 어느 것에나 접근할 수 있습니다.

예를 들어 `[rsp+8]`은 `[rsp]` 바로 _뒤_ 의 8바이트 값을, `[rsp+16]`은 그다음 값을 읽는 식입니다.
일반적으로 `[rsp+N]`은 주소 `rsp+N`의 메모리를 읽습니다:

```text
    Address    | Contents
  +---------------------------+
  | rsp        | value 0      |  <-- [rsp]
  +---------------------------+
  | rsp+8      | value 1      |  <-- [rsp+8]
  +---------------------------+
  | rsp+16     | value 2      |  <-- [rsp+16]
  +---------------------------+
  | ...        | ...          |
  +---------------------------+
```

이 오프셋들이 8의 배수로 가는 것이 보일 것입니다.
숫자나 메모리 주소처럼 스택에 있는 많은 값이 8바이트(64비트) 폭이라, 연달아 있는 값들이 8바이트씩 떨어져 있기 때문입니다.
하지만 이것은 대체로 관례입니다. 실제로 스택도 다른 메모리 영역과 마찬가지로 개별 바이트가 이어진 연속된 영역이지만, 지금은 스택을 8바이트/64비트 값들의 모음으로 다루겠습니다.

이 챌린지에서는 `rsp`에서 128바이트 떨어진 곳에 비밀 값을 숨겨 두었습니다.
`[rsp+128]`의 값을 읽어 종료 코드로 쓰세요!
