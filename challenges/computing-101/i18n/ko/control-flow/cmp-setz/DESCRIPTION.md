지금까지 여러분의 프로그램은 꽤 단순했습니다. 값을 옮기고, 메모리에서 읽고, 시스템 콜을 호출했죠.
하지만 실제 프로그램은 _판단_ 을 내려야 합니다. "이 조건이 참이면 이것을 하고, 아니면 저것을 하라"처럼요.
이것이 **제어 흐름(control flow)** 의 토대이며, 값을 _비교_ 하는 것에서 시작합니다.

x86 어셈블리에서 비교는 `cmp` 명령어로 합니다.
`cmp`는 첫 번째 피연산자에서 두 번째 피연산자를 빼서 두 값을 비교합니다.
중요한 점은 **`cmp`는 뺄셈의 결과를 여러분이 직접 볼 수 있는 곳에 저장하지 않는다** 는 것입니다.
대신 그 결과가 어땠는지에 따라 CPU 내부의 **플래그(flag)** 를 갱신합니다.

예를 들면:

```asm
cmp rdi, 42
```

이것은 내부적으로 `rdi - 42`를 계산하지만 `rdi`는 바뀌지 _않습니다_.
대신 CPU는 **제로 플래그(Zero Flag, ZF)** 라는 특별한 비트를 설정합니다. 뺄셈 결과가 0이면(즉 두 값이 같으면) ZF가 1이 됩니다.
`rdi`에 `42`가 들어 있다면 `42 - 42 = 0`이므로 ZF는 1이 됩니다.
`rdi`에 다른 값이 들어 있다면 결과가 0이 아니므로 ZF는 0이 됩니다.

좋습니다. `cmp` 뒤에 CPU는 두 값이 같았는지 압니다.
그런데 그 정보를 실제로 어떻게 _쓸까요_?

플래그를 곧바로 레지스터로 `mov`할 수는 없습니다.
대신 x86은 현재 플래그에 따라 바이트 크기의 목적지에 `0`이나 `1`을 쓰는 "조건부 설정" 명령어 무리를 제공합니다.

여기서 쓸 것은 `setz`("Set if Zero")입니다:

```asm
setz dil
```

이것은 제로 플래그를 확인해서:
- ZF = 1이면(값이 **같았고** 뺄셈 결과가 0이면) `dil`에 `1`을 씁니다.
- ZF = 0이면(값이 **같지 않았으면**) `dil`에 `0`을 씁니다.

간단합니다. `1`은 "그래, 일치했다!"이고 `0`은 "아니, 일치하지 않았다"입니다.
반대로 동작하는 `setnz`("Set if Not Zero")도 있지만 여기서는 필요 없습니다.

그런데 `dil`은 무엇일까요?
지금까지는 `rdi`, `rax`, `rsp` 같은 64비트 레지스터를 다뤘습니다.
그런데 `setz` 명령어는 한 바이트(8비트)만 씁니다.
다행히 64비트 레지스터의 일부에 접근할 수 있습니다.
`rdi`의 경우:

- `rdi`는 64비트 전체입니다
- `dil`은 가장 낮은 8비트, 즉 r**di**의 **l**ow 바이트입니다

`setz dil`이라고 쓰면 `rdi`의 가장 낮은 바이트에만 `0`이나 `1`을 넣고, 위쪽 바이트는 그대로 둡니다.
`rdi`는 `exit` 시스템 콜에 넘기는 값이지만, 리눅스는 그 값의 낮은 8비트만 프로세스의 종료 상태로 보고합니다.
그래서 여기서는 `dil`만 바꿔도 충분합니다. `rdi`의 위쪽 바이트가 무엇이든 눈에 보이는 상태는 `1`(같음!) 또는 `0`(다름!)이 됩니다.

`cmp`에 대해 한 가지 더. 레지스터와 즉시값을 비교할 수도 있고(`cmp rdi, 42`), 메모리 위치와 즉시값을 비교할 수도 있습니다(`cmp QWORD PTR [rsp], 42`).
하지만 두 메모리 위치를 한 번에 비교할 수는 **없습니다**. 피연산자 중 최대 하나만 메모리 역참조일 수 있습니다.

이제 챌린지입니다. [스택](/computing-101/the-stack) 모듈에서 `[rsp]`에 `argc`, 즉 프로그램 이름을 포함한 커맨드 라인 인자의 개수가 들어 있다는 것을 떠올려 보세요.
다음과 같은 프로그램을 작성하세요:

1. `argc`를 `42`와 비교합니다(먼저 argc를 레지스터로 옮기든, 메모리와 직접 비교하든 상관없습니다).
2. `setz dil`로 종료 코드를 설정합니다. argc가 42면 `1`, 아니면 `0`입니다.
3. 종료합니다.
