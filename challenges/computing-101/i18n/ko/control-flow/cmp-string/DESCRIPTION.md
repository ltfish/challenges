앞 챌린지에서는 `cmp`와 `jne`로 문자 하나를 확인하고 실패 경로로 분기했습니다.
그런데 문자 하나를 확인하는 것으로 충분한 경우는 드뭅니다. 비밀번호, 명령, 파일 이름은 모두 여러 문자로 이루어진 _문자열_ 이죠.

좋은 소식은, 문자열 전체를 확인하는 데 필요한 것은 이미 다 알고 있다는 것입니다!
그저 문자마다 `cmp` / `jne` 쌍을 이어 붙이되, 모두 같은 `fail` 레이블로 점프하게 하면 됩니다:

```asm
mov rax, [rsp+16]       ; load argv[1] pointer

cmp BYTE PTR [rax], 'Y'
jne fail

cmp BYTE PTR [rax+1], 'E'
jne fail

cmp BYTE PTR [rax+2], 'S'
jne fail
```

각 비교가 문자열의 문자 하나를 확인합니다.
[컴퓨터 메모리](/computing-101/computer-memory) 모듈에서 `[rax+1]`이 `rax`의 주소에서 _한 칸 뒤_ 의 바이트에 접근하고, `[rax+2]`는 두 칸 뒤라는 것을 떠올려 보세요.
문자열은 메모리에 연속된 바이트로 저장되므로, `[rax]`가 첫 문자, `[rax+1]`이 두 번째, `[rax+2]`가 세 번째입니다.

어떤 문자든 맞지 않으면 `jne`가 곧바로 `fail`로 점프하고, 프로그램은 나머지를 확인하지 않습니다.
_모든_ 비교를 통과했을 때에만(모든 문자가 일치했을 때에만) 실행이 성공 경로로 떨어집니다.

이것이 많은 문자열 비교가 가장 낮은 수준에서 동작하는 방식입니다. 바이트 단위로 비교하고, 첫 불일치에서 빠져나오는 것이죠.

이제 연습해 봅시다.
첫 번째 인자가 문자열 `"pwn"`으로 시작하는지 확인하는 프로그램을 작성하세요:

1. `[rsp+16]`에서 첫 번째 인자의 포인터를 불러옵니다.
2. 오프셋 0의 바이트를 `'p'`와 비교합니다. 맞지 않으면 `jne fail`.
3. 오프셋 1의 바이트를 `'w'`와 비교합니다. 맞지 않으면 `jne fail`.
4. 오프셋 2의 바이트를 `'n'`과 비교합니다. 맞지 않으면 `jne fail`.
5. 성공 경로를 구현합니다: `exit(0)`.
6. `fail:` 레이블을 만들고 `exit(1)`을 구현합니다.
