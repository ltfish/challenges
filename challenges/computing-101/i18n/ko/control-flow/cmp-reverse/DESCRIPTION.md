앞 챌린지에서는 문자열을 한 글자씩 비교하는 어셈블리를 작성했습니다.
자, 이제 입장이 뒤바뀌었습니다!
_저희가_ 프로그램을 작성했고, _여러분이_ 그것이 무슨 일을 하는지 알아내야 합니다!

`/challenge/reverse-me`에 SUID 바이너리가 있습니다.
이 프로그램은 커맨드 라인 인자를 받아 숨겨진 비밀번호와 한 바이트씩 비교하고(익숙하죠?), 비밀번호가 맞으면 플래그를 읽어 출력합니다.
문자가 하나라도 틀리면 조용히 종료합니다.

어떻게 풀까요?
프로그램의 디스어셈블리를 읽고, `cmp` 명령어를 분석해서, 프로그램이 원하는 비밀번호를 알아낸 뒤 올바른 인자와 함께 실행해야 합니다.

이미 도구는 갖추고 있습니다!
[소프트웨어 들여다보기](/computing-101/introspecting) 모듈에서 `objdump -d -M intel /challenge/reverse-me`가 바이너리를 디스어셈블해 어셈블리 명령어를 보여준다는 것을 떠올려 보세요.
앞 챌린지에서 작성한 것과 비슷한 `cmp` 명령어가 보이겠지만, 익숙한 `''` 따옴표 문자 대신 비교 대상 값이 16진수로 적혀 있을 것입니다.
그 비교의 즉시값이 *바로* 비밀번호 문자이며, 16진수 ASCII 값으로 인코딩되어 있습니다.

예를 들어 디스어셈블리에 이런 것이 보인다고 해봅시다:

```
cmp    BYTE PTR [rax],0x70
```

여기서 `0x70`은 `'p'`의 ASCII 코드입니다.
ASCII 값의 전체 목록은 `man ascii` 명령으로 볼 수 있습니다.

비밀번호 문자를 전부 복원했으면 프로그램을 직접 실행하세요:

```console
hacker@dojo:~$ /challenge/reverse-me YOUR_PASSWORD_HERE
```

----
**경고**:
`/challenge/reverse-me`는 **SUID** 바이너리입니다. `/flag`를 읽을 수 있도록 높은 권한으로 실행되죠.
그런데 **프로그램을 디버깅하면 SUID 권한이 떨어지므로**, gdb 아래에서 실행하면 내부의 `open("/flag")` 시스템 콜이 **조용히** 실패합니다.
바이너리를 _이해_ 하고 비밀번호를 알아내는 데는 gdb나 `objdump`를 쓰되, 플래그를 얻으려면 (gdb 밖에서) **직접** 실행하세요.
