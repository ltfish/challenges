앞 챌린지들에서는 `setz`로 비교 결과를 `dil`에 `0`이나 `1`로 담아 그것을 곧바로 종료 코드로 넘겼습니다.
깔끔한 요령이었지만 한계가 있습니다.
값이 같은지 여부에 따라 프로그램이 아예 다른 _행동_ 을 하게 하려면 어떻게 할까요?

그럴 때 등장하는 것이 **조건부 점프(conditional jump)** 입니다.
비교 결과를 레지스터에 기록하는 대신, `cmp`의 결과에 따라 코드의 다른 부분으로 _점프_ 하라고 CPU에 알려줄 수 있습니다.
우리 목적에 가장 쓸모 있는 조건부 점프는 `jne`(**J**ump if **N**ot **E**qual)입니다:

```asm
cmp BYTE PTR [rax], 'p'
jne fail
```

`cmp` 뒤에 값이 같지 _않으면_ CPU는 `fail`이라고 이름 붙은 위치로 점프합니다.
이럴 때 (길이나 코드의) "분기를 탄다"고 표현합니다.
값이 같았다면 CPU는 그냥 다음 명령어로 진행합니다.
분기를 타지 _않는_ 이 동작을 다음 명령어로 "떨어진다(falls through)"고 표현합니다.

내부적으로 `jne`는 `cmp`가 설정한 제로 플래그(ZF)를 확인합니다. ZF = 0일 때(뺄셈 결과가 0이 아니어서 값이 달랐을 때) 점프하죠.
반대로 값이 _같을_ 때 점프하는 `je`(**J**ump if **E**qual)도 있습니다.

그런데 `fail`은 무엇일까요?
**레이블(label)** 입니다. 코드의 어떤 위치에 붙이는 이름이죠.
레이블은 기계 명령어를 만들어 내지 않고, 그저 점프 명령어가 참조할 수 있는 자리를 표시합니다.
이름 뒤에 콜론을 붙여 정의합니다:

```asm
fail:
  mov rdi, 1
  mov rax, 60
  syscall
```

어셈블러가 레이블을 주소로 바꿔주므로 `jne fail`은 실제 기계어에서 `jne <address>` 같은 것이 됩니다.
레이블 이름은 거의 무엇이든(`fail`, `error`, `done`, `loop` 등) 지을 수 있지만, 그 위치에서 무슨 일이 일어나는지 설명하는 이름이 좋습니다.

조건부 점프가 있으면 프로그램은 두 갈래의 실행 _경로_ 를 가질 수 있습니다:

```
main:
  [load and compare]
  jne fail          ← jump to fail if NOT equal

success:
  mov rdi, 0
  mov rax, 60
  syscall

fail:
  mov rdi, 1
  mov rax, 60
  syscall
```

비교가 성공하면(값이 같으면) 실행이 success 경로로 떨어져 `0`으로 종료합니다. 리눅스 프로그램에서 표준적인 "성공" 종료 코드죠.
비교가 실패하면(값이 다르면) 실행이 `fail` 레이블로 점프해 `1`로 종료하며, 이는 프로그램 실패를 나타냅니다.

물론 이것은 단순한 예시지만, 단순한 것부터 시작합시다!
챌린지는 이것입니다. `setz` 대신 조건부 점프로 `argv[1]`의 첫 문자가 `'p'`인지 확인하는 프로그램을 작성하세요:

1. `[rsp+16]`에서 `argv[1]` 포인터를 레지스터로 불러옵니다.
2. 그 주소의 `BYTE PTR`를 `'p'`와 비교합니다.
3. `jne fail` --- 문자가 다르면 실패 경로로 점프합니다.
4. "떨어지는" 성공 경로를 작성합니다(`exit(0)`).
5. `fail:` 레이블을 정의하고 실패 경로를 작성합니다(`exit(1)`).

까다로운 점은, (점프를 타지 _않는_) 성공 경로가 `jne` 명령어와 그 `jne`가 가리키는 실패 경로 사이에 있다는 것입니다.
머릿속에 넣는 데 시간이 좀 걸리겠지만 곧 익숙해질 것입니다!
