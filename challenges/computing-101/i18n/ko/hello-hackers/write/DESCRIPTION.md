텍스트를 출력하는 법을 배워봅시다!

당연하게도 프로그램은 시스템 콜을 호출해서 화면에 텍스트를 씁니다.
구체적으로는 `write` 시스템 콜이며, 시스템 콜 번호는 `1`입니다.
다만 write 시스템 콜은 _어떤_ 데이터를 _어디에_ 쓸지도 인자로 지정해야 합니다.

[리눅스 루미나리움](/linux-luminarium) 도장의 [파이핑 연습하기](/linux-luminarium/piping) 모듈에서 _파일 디스크립터_ (FD) 개념을 기억할 것입니다.
다시 정리하면, 모든 프로세스는 세 개의 FD를 가지고 시작합니다:

- **FD 0:** 표준 *입력* 은 프로세스가 입력을 받아들이는 채널입니다. 예를 들어 셸은 여러분이 입력한 명령어를 표준 입력으로 읽습니다.
- **FD 1:** 표준 *출력* 은 프로세스가 평범한 데이터를 내보내는 채널입니다. 앞선 챌린지에서 찍힌 플래그나 `ls` 같은 유틸리티의 출력이 여기에 해당합니다.
- **FD 2:** 표준 *에러* 는 프로세스가 오류 내용을 내보내는 채널입니다. 예를 들어 명령어를 잘못 입력하면, 셸은 그런 명령어가 없다는 사실을 표준 에러로 알려줍니다.

바로 이것이 `write` 시스템 콜에서 데이터를 _어디에_ 쓸지 지정하는 방법입니다!
`exit` 시스템 콜의 첫 번째이자 유일한 인자는 종료 코드(`mov rdi, 42`)였고, `write`의 첫 번째(이번에는 유일하지 않은!) 인자는 파일 디스크립터입니다.
표준 출력에 쓰고 싶다면 `rdi`를 1로 설정합니다.
표준 에러에 쓰고 싶다면 `rdi`를 2로 설정합니다.
아주 간단하죠!

이제 _무엇을_ 쓸지가 남았습니다.
`write` 시스템 콜에 또 다른 레지스터 인자로 쓸 내용을 지정하는 세상을 상상할 수도 있습니다.
하지만 레지스터에는 많은 데이터가 들어가지 않으므로, 이 챌린지 설명처럼 긴 글을 쓰려면 `write` 시스템 콜을 여러 번 호출해야 할 것입니다.
상대적으로 이는 성능 비용이 큽니다. CPU가 여러분 프로그램의 명령어를 실행하다가 리눅스 자체의 명령어를 실행하도록 전환하고, 이런저런 관리 작업을 하고, 실제 픽셀이 화면에 뜨도록 하드웨어와 상호작용한 뒤 다시 돌아와야 하니까요.
이것은 느리므로 시스템 콜을 호출하는 횟수를 되도록 줄이려 합니다.

물론 해결책은 여러 문자를 한 번에 쓰는 것입니다.
`write` 시스템 콜은 "무엇을"에 해당하는 인자를 _둘_ 로 받습니다. (메모리에서) _어디부터_ 쓸지와 _몇 글자_ 를 쓸지죠.
이 인자들은 `write`의 두 번째와 세 번째 인자로 넘어갑니다.
`strace`에서 배운 C 비슷한 문법으로 쓰면 이렇습니다:

```c
write(file_descriptor, memory_address, number_of_characters_to_write)
```

좀 더 구체적인 예로, 어떤 메모리 주소에서 시작해 10글자를 표준 출력(파일 디스크립터 1)에 쓰고 싶다면 이렇게 됩니다:

```c
write(1, memory_address, 10);
```

와, 간단하네요!
그럼 이 인자들을 실제로 어떻게 지정할까요?

1. 위에서 정리했듯 시스템 콜의 첫 번째 인자는 `rdi` 레지스터로 넘깁니다.
2. 두 번째 인자는 `rsi` 레지스터로 넘깁니다.
   리눅스에서 합의된 관례상 `rsi`가 시스템 콜의 두 번째 인자로 쓰입니다.
3. 세 번째 인자는 `rdx` 레지스터로 넘깁니다.
   이 모듈 전체에서 가장 헷갈리는 부분입니다. (첫 번째 인자를 담는) `rdi`와 `rdx`는 이름이 너무 비슷해서 뒤섞기 아주 쉬운데, 안타깝게도 이 이름은 역사적인 이유로 이렇게 굳어졌고 앞으로도 그럴 것입니다.
   어쩔 수 없죠...
   그저 조심해야 하는 부분입니다.
   "`rdi`는 **i**nitial 인자, `rdx`는 **x**tra 인자" 같은 연상법을 쓰면 어떨까요?
   아니면 이름이 비슷한 친구들을 구별해서 기억해야 하는 상황이라고 생각하면 괜찮을 것입니다.

그리고 물론 `write`의 시스템 콜 번호 `1`을 `rax`에 넣습니다.
`rdi`와 `rdx`의 혼동만 빼면 정말 쉽습니다!

이제 시스템 콜 번호를 설정하는 법과 나머지 레지스터를 설정하는 법을 알게 되었습니다.
그런데 써야 할 데이터는 메모리 어디에 있을까요?

이 챌린지에서 여러분의 프로그램은 이런 식으로 커맨드 라인 인자와 함께 실행됩니다:

```text
/tmp/your-program H
```

프로그램이 인자와 함께 실행되면 스택이 각 인자를 가리키는 _포인터_ 를 저장한다는 것을 떠올려 보세요.
이것들은 메모리에 저장된 _주소_ 입니다. `[rsp+16]`은 인자 텍스트를 직접 담고 있는 것이 아니라, 그 텍스트가 있는 _주소_ 를 담고 있습니다.

따라서 첫 번째 인자의 메모리 주소를 얻으려면, 전에 해봤듯 스택에서 포인터를 불러오기만 하면 됩니다!

```asm
mov rsi, [rsp+16]
```

이렇게 하면 첫 번째 인자 텍스트의 메모리 주소가 `rsi`에 들어갑니다. `write`가 두 번째 인자로 원하는 바로 그것이죠!

여러분의 프로그램은 첫 번째 인자로 문자 하나를 받아 실행됩니다.
`write`를 호출해 그 한 글자를(지금은요! 여러 글자 쓰기는 나중에 합니다) 표준 출력에 쓰면 플래그를 드리겠습니다!
