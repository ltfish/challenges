지금까지 여러분의 프로그램은 stdin과 stdout하고만 상호작용했는데, 디스크의 파일은 어떨까요?
파일에 접근하려면 먼저 `open` 시스템 콜로 그것을 열어야 합니다.

`open` 시스템 콜(시스템 콜 번호 `2`)은 파일 이름 문자열의 포인터를 받아, 그 파일을 가리키는 새 파일 디스크립터를 반환합니다:

```c
open("/flag", 0);
```

두 번째 인자는 파일에 대한 추가 모드와 권한을 지정하는데, `0`은 기본값인 읽기 전용을 요청합니다.

`open`의 레지스터도 같은 관례를 따릅니다:

| 레지스터 | 용도 |
|----------|---------|
| `rax`    | `2` (`open`의 시스템 콜 번호) |
| `rdi`    | 메모리에 있는 파일 이름 문자열의 포인터 |
| `rsi`    | `0` (읽기 전용) |

`open`이 반환하면 `rax`에 새 파일 디스크립터(fd) 번호가 들어 있습니다.
파일 디스크립터 0은 stdin, 1은 stdout, 2는 stderr라는 것을 떠올려 보세요.
그 밖에 열린 파일은 3부터 올라가는 다른 파일 디스크립터로 표현됩니다!
앞서 stdin에 했던 것처럼 이 fd를 `read`의 첫 번째 인자로 쓰는데, 이번에는 `read`가 그 파일에서 읽습니다.

파일 이름은 어떻게 메모리에 불러올까요?
이 레벨에서는 플래그의 경로(`/flag`)가 프로그램의 첫 번째 인자로 넘어옵니다.
그것을 불러오는 법은 이미 압니다: `mov rdi, [rsp+16]`.

여러분의 프로그램은 다음을 해야 합니다:

1. 파일 이름의 포인터(첫 번째 인자인 `[rsp+16]`에 저장됨)를 `rdi`로 불러옵니다
2. 두 번째 인자로 기본값인 읽기 접근을 지정합니다(`rsi`를 `0`으로).
3. 그것을 `open`합니다(시스템 콜 `2`)
4. 반환된 fd에서 메모리로 `read`합니다. `open`이 반환한 fd는 `rax`에 있으니, `read`의 첫 번째 인자를 위해 `rdi`로 옮기세요(write의 시스템 콜 번호를 설정하기 _전에_ 하세요!). 플래그보다 넉넉한 크기로 읽으세요.
5. `read`가 반환한 바이트 수만큼 정확히 stdout에 `write`합니다(read-exact에서처럼 `mov rdx, rax`)
6. 코드 `42`로 `exit`합니다(시스템 콜 `60`)

**디버깅:**
잘 안 되나요?
`strace`로 시스템 콜이 어떻게 동작하는지 보세요. 각 시스템 콜이 어떤 인자를 받고 무엇을 반환하는지 정확히 보여줍니다.
`open`이 `-1`을 반환한다면 파일 이름 포인터를 다시 확인하세요.
`read`가 `0`을 반환한다면 `open`이 준 파일 디스크립터가 잘못되었을 수 있습니다.
