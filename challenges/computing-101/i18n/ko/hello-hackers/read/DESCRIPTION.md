이제 `write`로 stdout에 데이터를 내보내는 법을 압니다.
그런데 프로그램은 입력 데이터를 어떻게 받을까요?
stdin에서 `read`합니다!

`write`와 마찬가지로 `read`도 파일 디스크립터와 메모리 사이로 데이터를 옮기는 시스템 콜이며, 시스템 콜 번호는 `0`입니다.
`read`의 경우 주어진 파일 디스크립터에서 일정한 양의 바이트를 읽어 메모리에 저장합니다.
C 스타일 문법은 `write`와 같습니다:

```c
read(0, some_address, 5);
```

이것은 파일 디스크립터 `0`(stdin)에서 `5`바이트를 읽어 `some_address`부터 시작하는 메모리에 넣습니다.
따라서 stdin에 `HELLO HACKERS`를 입력하거나 파이프로 넣으면, 위 `read` 호출의 결과로 메모리는 이렇게 됩니다:

```text
     Address     │ Contents
+───────────────────────────+
│ some_address   │ 48       │
│ some_address+1 │ 45       │
│ some_address+2 │ 4c       │
│ some_address+3 │ 4c       │
│ some_address+4 │ 4f       │
+───────────────────────────+
```

저 숫자들은 무엇일까요??
_ASCII_ 로 인코딩된 글자를 _16진수_ 로 나타낸 것입니다.
이 말들이 이해되지 않는다면 [데이터 다루기](/fundamentals/data-dealings) 모듈의 절반쯤을 훑어보고 다시 오세요!

이 레벨에서는 `read`와 앞서 익힌 `write`를 결합합니다.
플래그가 프로그램의 stdin으로 파이프되어 들어오며, 128바이트입니다.
여러분의 프로그램은 다음을 해야 합니다:

1. 먼저 stdin에서 128바이트를 프로그램 메모리로 `read`합니다
2. 그 메모리 위치에서 128바이트를 stdout으로 `write`합니다
3. 마지막으로 종료 코드 `42`로 종료합니다.

그런데 어떤 주소를 써야 할까요?
유효하고 쓰기 가능한 곳이 필요한데, 이미 그런 곳을 하나 알고 있습니다. 바로 스택입니다!
`rsp` 레지스터가 스택 꼭대기를 가리키고, 거기에는 쓸 수 있는 공간이 넉넉합니다.
그러니 `rsp`를 메모리 주소로 쓰면 됩니다: `mov rsi, rsp`.
