이제 메모리의 포인터를 프로처럼 역참조할 수 있습니다!
그런데 포인터가 늘 필요한 데이터를 곧바로 가리키는 것은 아닙니다.
예를 들어 포인터가 어떤 데이터 묶음(이를테면 책 한 권 전체)을 가리키고 있어서, 필요한 특정 데이터를 얻으려면 그 묶음 안쪽을 참조해야 할 때가 있습니다.

예를 들어 포인터(가령 `rdi`)가 메모리에 있는 숫자 나열을 가리킨다고 해봅시다:

```text
    Address │ Contents
  +────────────────────+
┌▸│ 133700  │ 50       │
│ │ 133701  │ 42       │
│ │ 133702  │ 99       │
│ │ 133703  │ 14       │
│ +────────────────────+
│
└────────────────────────┐
                         │
   Register │ Contents   │
  +────────────────────+ │
  │ rdi     │ 133700   │─┘
  +────────────────────+
```


그 나열의 두 번째 숫자를 원한다면 이렇게 하면 됩니다:

```assembly
mov rax, [rdi+1]
```

와, 아주 간단하네요!
메모리 용어로 이 숫자 칸 하나하나를 _바이트_ 라고 부릅니다. 각 메모리 주소는 메모리의 특정 바이트를 나타냅니다.
위 예시는 `rdi`가 가리키는 메모리 주소에서 1바이트 뒤의 메모리에 접근합니다.
메모리 용어로 이 1바이트 차이를 _오프셋(offset)_ 이라고 부르므로, 이 예시에서는 `rdi`가 가리키는 주소로부터 오프셋 1이 있는 것입니다.

이 개념을 연습해 봅시다.
앞서처럼 `rdi`가 비밀 값을 가리키도록 초기화하겠지만, _곧바로_ 가리키지는 않습니다.
이번에는 비밀 값이 `rdi`가 가리키는 곳에서 8바이트 오프셋에 있으며, 대략 이런 모습입니다:

```text
    Address │ Contents
  +────────────────────+
┌▸│ 31337   │ 0        │
│ │ 31337+1 │ 0        │
│ │ 31337+2 │ 0        │
│ │ 31337+3 │ 0        │
│ │ 31337+4 │ 0        │
│ │ 31337+5 │ 0        │
│ │ 31337+6 │ 0        │
│ │ 31337+7 │ 0        │
│ │ 31337+8 │ ???      │
│ +────────────────────+
│
└────────────────────────┐
                         │
   Register │ Contents   │
  +────────────────────+ │
  │ rdi     │ 31337    │─┘
  +────────────────────+
```

물론 실제 메모리 주소는 `31337`이 아닙니다.
무작위로 골라 `rdi`에 저장하겠습니다.
`rdi`를 오프셋 `8`로 역참조해서 플래그를 얻으세요!
