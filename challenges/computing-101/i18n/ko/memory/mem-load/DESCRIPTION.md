프로그램이 보기에 컴퓨터 메모리는 데이터가 사는 거대한 공간입니다.
거리에 늘어선 집처럼 메모리의 모든 부분에는 숫자로 된 _주소_ 가 있고, 거리의 집처럼 그 번호는 (대체로) 순서대로 이어집니다.
현대 컴퓨터에는 어마어마한 양의 메모리가 있고, 전형적인 현대 프로그램이 보는 메모리에는 사실 큰 빈틈이 있습니다(집이 지어지지 않아 그 주소가 건너뛰어진 거리 구간을 떠올려 보세요).
하지만 이것들은 세부일 뿐입니다. 요점은 컴퓨터가 데이터를 메모리에 대체로 순차적으로 저장한다는 것입니다.

이 레벨에서는 메모리에 저장된 데이터에 접근하는 연습을 합니다.
어떻게 할까요?
레지스터에 값을 옮길 때 이렇게 했던 것을 떠올려 보세요:

```assembly
mov rdi, 31337
```

이렇게 하면 `rdi`의 값은 `31337`이 됩니다.
좋습니다.
그런데 같은 명령어로 메모리에 접근할 수도 있습니다!
두 번째 인자를 메모리에 접근할 주소로 쓰는 다른 형태가 있습니다!
메모리가 이렇게 생겼다고 해봅시다:

```text
  Address │ Contents
+────────────────────+
│ 31337   │ 42       │
+────────────────────+
```

메모리 주소 31337에 있는 내용에 접근하려면 이렇게 하면 됩니다:

```assembly
mov rdi, [31337]
```

CPU가 이 명령어를 실행할 때, 당연히 `31337`이 원시 값이 아니라 _주소_ 라는 것을 이해합니다.
명령어를 CPU에게 할 일을 알려주는 사람이라고 생각하고 "거리의 집" 비유를 이어가면, 명령어(사람)는 CPU에게 데이터를 그냥 건네주는 대신 _거리의 어떤 집을 가리킵니다_.
그러면 CPU는 그 주소로 가서 초인종을 누르고 현관문을 열어, 안에 있는 데이터를 끌어내 `rdi`에 넣습니다.
따라서 이 맥락에서 `31337`은 _메모리 주소_ 이며, 그 메모리 주소에 저장된 데이터를 _가리키는_ 역할을 합니다.
이 명령어가 실행되고 나면 `rdi`에 저장된 값은 `42`가 됩니다!

실제로 해봅시다!
메모리 주소 `133700`에 비밀 숫자를 저장해 두었습니다:

```text
  Address │ Contents
+────────────────────+
│ 133700  │ ???      │
+────────────────────+
```

이 비밀 숫자를 가져와서 프로그램의 종료 코드로 써야 합니다.
그러려면 그 값을 `rdi`로 읽어 들여야 하는데, 기억하듯 `rdi`의 값은 `exit`의 첫 번째 인자이자 종료 코드로 쓰입니다.
행운을 빕니다!
