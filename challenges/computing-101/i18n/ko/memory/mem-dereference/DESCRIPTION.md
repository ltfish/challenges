`133700`에 접근하는 것이 좋았나요, `123400`에 접근하는 것이 좋았나요?
그 답이 여러분의 성격을 말해줄지도 모르지만, 기술적으로는 딱히 중요하지 않습니다.
사실 대부분의 경우 프로그램을 작성할 때 실제 메모리 주소를 직접 다루지는 않습니다!

어떻게 그럴 수 있을까요?
보통 메모리 주소는 레지스터에 저장하고, 그 레지스터의 값으로 메모리의 데이터를 가리킵니다!
이런 메모리 구성에서 시작해 봅시다:

```text
  Address │ Contents
+────────────────────+
│ 133700  │ 42       │
+────────────────────+
```

그리고 다음 어셈블리 조각을 봅시다:

```assembly
mov rax, 133700
```

이제 상황은 이렇습니다:

```text
    Address │ Contents
  +────────────────────+
┌▸│ 133700  │ 42       │
│ +────────────────────+
│
└────────────────────────┐
                         │
   Register │ Contents   │
  +────────────────────+ │
  │ rax     │ 133700   │─┘
  +────────────────────+
```

`rax`는 이제 우리가 불러오고 싶은 데이터의 주소에 해당하는 값을 담고 있습니다!
그것을 불러와 봅시다:

```assembly
mov rdi, [rax]
```

여기서 우리는 메모리에 접근하고 있지만, 메모리를 읽을 때 `133700` 같은 고정된 주소를 지정하는 대신 `rax`에 저장된 값을 메모리 주소로 쓰고 있습니다.
메모리 주소를 담고 있으므로 `rax`는 우리가 접근하려는 데이터를 _가리키는_ _포인터(pointer)_ 입니다!
`rax`가 저장한 주소를 직접 적는 대신 `rax`를 써서 그것이 참조하는 메모리 주소에 접근할 때, 이를 포인터를 _역참조(dereference)_ 한다고 부릅니다.
위 예시에서 우리는 `rax`를 _역참조_ 해서 그것이 가리키는 데이터(주소 `133700`에 있는 값 `42`)를 `rdi`로 불러옵니다.
멋지네요!

이것은 또 하나의 요점을 분명히 해 줍니다. 이 레지스터들은 _범용_ 입니다!
지금까지 챌린지에서 `rax`를 시스템 콜 번호로 써 왔다고 해서 다른 용도로 못 쓰는 것은 아닙니다.
여기서는 메모리에 있는 비밀 데이터를 가리키는 포인터로 쓰였습니다.

마찬가지로 레지스터 안의 _데이터_ 에도 내재된 용도는 없습니다.
`rax`가 값 `133700`을 담고 있을 때 `mov rdi, [rax]`라고 쓰면 CPU는 그 값을 역참조할 메모리 주소로 씁니다.
하지만 같은 조건에서 `mov rdi, rax`라고 쓰면 CPU는 그저 `133700`을 `rdi`에 넣어줄 뿐입니다.
CPU에게 데이터는 그냥 데이터이며, 서로 다르게 쓰일 때에만 구별이 생깁니다.

이 챌린지에서는 메모리에 저장한 비밀 데이터의 주소를 `rax`에 넣어 두었습니다.
`rax`를 역참조해서 비밀 데이터를 `rdi`로 불러오고, 그것을 프로그램의 종료 코드로 써서 플래그를 얻으세요!
